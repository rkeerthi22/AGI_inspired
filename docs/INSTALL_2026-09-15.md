# INSTALL — AGI_like clean-machine installer (2026-09-15)

A single idempotent installer that takes a fresh Windows 11 box to a ready AGI_like
harness by **orchestrating the existing provisioning scripts** (it does not
reimplement what they do — it calls them). It **fails closed** at every
boundary-attesting step: it never reports "ready" when the egress boundary or
attestation could not be established.

## Run it

```powershell
# Full install (requires Administrator; provisions the boundary + WFP + attestation)
.\scripts\install.ps1

# Non-mutating readiness audit (no Administrator required, no mutations)
.\scripts\install.ps1 -Check

# Fast audit that skips the test gate
.\scripts\install.ps1 -Check -SkipGate

# Dev machine without Admin: skip the three-identity + WFP boundary steps
# (the installer reports them as MISSING; the product is NOT deployment-ready)
.\scripts\install.ps1 -Check -SkipIdentity
```

## What the installer does (7 steps, in order)

1. **Prerequisites** — Windows 11 (build >= 22000), PowerShell 5.1+, Python 3.11+,
   git on PATH. Fails closed with a clear message if any is missing.
2. **Repo + dependencies** — invokes `scripts/bootstrap.ps1` (venv +
   hash-verified Python deps). In `-Check` mode this only verifies the venv exists.
3. **Operator Ed25519 attestation keypair** — invokes `scripts/_installer_keypair.py`.
   Generates the keypair if absent (`operator_auth._generate_keypair`), or audits it
   with `--check`. **The private key is never printed** — only the public-key
   fingerprint (sha256). The keypair is stored in Windows Credential Manager
   (fallback: Hermes home, `0o600`; never in the repo).
4. **Three-identity containment boundary** — invokes `scripts/deploy_three_identity.ps1`
   (creates `AGI_Signer` / `AGI_Controller` / `AGI_Worker`). In `-Check` mode it runs
   `-Action Verify` (read-only). If the identity cannot be established, **fail-closed**
   — no no-boundary install proceeds.
5. **WFP egress boundary + signed attestation** — invokes
   `scripts/enforce_worker_firewall.ps1 -Action Apply` then `-Action Attest`
   (deny-by-default egress + signs `.harness/egress_attestation.signed`). If the
   attestation cannot be signed, fail-closed. (Keypair must exist first — step 3 —
   because Attest signs with the operator key.)
6. **ESTOP default-engaged** — invokes `scripts/_installer_estop.py`. A fresh install
   ships **paused**: the ESTOP sentinel is present by default. This helper **only
   engages or audits**; it **never disengages** ESTOP. Disengagement stays a separate
   controlled-window CLI operation (`orchestrator/execution_pause.py`).
7. **Test gate** — runs `python -B tests/run_all.py`; requires exit 0 with zero
   `[FAIL]`/`FAILED`/`ERROR` lines (the count N/N is read from output, not hardcoded).

A final **readiness summary** prints what is set up and what is operator-pending, and
exits 0 only if every hard step succeeded.

## Idempotency + safety

- Re-runnable: every step checks existing state before acting, so a second run
  repairs missing pieces without duplicating work.
- Fail-closed at every boundary-attesting step. `-Check` is a non-mutating audit
  that exits 1 with a per-step summary if anything is missing (not a crash).
- The `-Check` mode collects all hard failures before deciding the exit code, so
  the audit prints every step even when the machine is not ready.

## Operator-pending (NOT handled by this script)

The installer deliberately stops at the machine boundary. Two things remain for the
operator after a green install:

- **Provider credentials** — set via Windows Credential Manager (`orchestrator/secrets.py`),
  never via this script, never printed in any install log.
- **Egress allowlist domains** — approved via the policy manager. Egress widening is
  **operator-gated and deny-by-default**: each new domain is a new exfiltration surface,
  so the approve endpoint stays behind the bearer-auth operator token.

## Helper scripts

| Script | Role |
|---|---|
| `scripts/install.ps1` | The orchestrating installer / readiness auditor. |
| `scripts/_installer_keypair.py` | Ensure or audit the operator Ed25519 keypair. `--check` is read-only. |
| `scripts/_installer_estop.py` | Engage or audit the ESTOP sentinel. `--check` is read-only. Never disengages. |
| `scripts/bootstrap.ps1` | venv + hash-verified Python dependencies. |
| `scripts/deploy_three_identity.ps1` | Three-identity boundary (`-Action {Plan\|ProvisionAccounts\|InitializeKeys\|ConfigureAcls\|ConfigureFirewall\|InstallSignerService\|Verify\|Remove}`; `Verify` is non-mutating). |
| `scripts/enforce_worker_firewall.ps1` | WFP egress + attestation (`-Action {Verify\|Apply\|Remove\|Test\|Attest}`; `Verify` is non-mutating). |

## Verification

The installer contract is covered by `tests/test_installer.py` (unit tier): the
helpers run read-only in `--check` mode, never leak the private key,
`install.ps1` parses without syntax errors (PowerShell AST parse, not executed),
and declares the `-Check` / fail-closed contract. Run `python -B tests/run_all.py
--tier unit` to exercise it.
